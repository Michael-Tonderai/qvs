Behind login, like the search page that links here. WHAT THIS PAGE DOES NOT DO. It does not state whether the record is authentic. The view does not call verification.verify, because verification.py's guarantee that every attempt is audited holds only because its single caller writes the event - a second caller would inherit that obligation, and auditing internal browsing would change what the audit trail means. So this page shows what is registered and sends the reader to the public verification page to ask the other question. register_done.html takes the same shape for the same reason. That separation is not a limitation to apologise for. Retrieval answers "what does the register say"; verification answers "is this still what was signed". Two questions, two pages, one place where the second one is answered. {% endcomment %} {% block title %}{{ qualification.certificate_id }} - QVS{% endblock %} {% block content %}
